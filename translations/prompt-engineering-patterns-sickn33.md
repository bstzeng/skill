# 提示工程模式

掌握進階的提示工程技巧，以最大化 LLM 的效能、可靠性與可控性。

## 以下情況不要使用本技能

- 任務與提示工程模式無關
- 你需要此範圍以外的其他領域或工具

## 指示

- 釐清目標、限制與必要的輸入。
- 套用相關的最佳實務並驗證成果。
- 提供可執行的步驟與驗證方式。

## 以下情況使用本技能

- 為生產環境的 LLM 應用設計複雜的提示詞
- 最佳化提示詞的效能與一致性
- 實作結構化推理模式（思維鏈、思維樹）
- 建立具備動態範例選擇的少樣本學習系統
- 建立含變數插值、可重用的提示範本
- 除錯並修正會產生不一致輸出的提示詞
- 為專門的 AI 助理實作系統提示

## 核心能力

### 1. 少樣本學習（Few-Shot）
- 範例選擇策略（語意相似度、多樣性抽樣）
- 在範例數量與上下文視窗限制之間取得平衡
- 以輸入—輸出配對建構有效的示範
- 從知識庫動態檢索範例
- 透過策略性的範例選擇處理邊界情況

### 2. 思維鏈提示（Chain-of-Thought）
- 引導逐步推理
- 以「讓我們一步一步思考」進行零樣本 CoT
- 帶推理過程的少樣本 CoT
- 自我一致性技巧（抽樣多條推理路徑）
- 驗證與確認步驟

### 3. 提示詞最佳化
- 迭代修正的工作流程
- A/B 測試提示詞變體
- 衡量提示詞的效能指標（準確度、一致性、延遲）
- 在維持品質的同時減少 token 用量
- 處理邊界情況與失敗模式

### 4. 範本系統
- 變數插值與格式化
- 條件式的提示段落
- 多輪對話範本
- 以角色為基礎的提示組合
- 模組化的提示元件

### 5. 系統提示設計
- 設定模型的行為與限制
- 定義輸出格式與結構
- 確立角色與專業
- 安全準則與內容政策
- 設定情境與背景資訊

## 關鍵模式

### 漸進式揭露
從簡單的提示詞開始，只在需要時才增加複雜度：

1. **第 1 級**：直接指示
   - 「摘要這篇文章」

2. **第 2 級**：加上限制
   - 「用 3 個重點摘要這篇文章，聚焦在主要發現」

3. **第 3 級**：加上推理
   - 「閱讀這篇文章，找出主要發現，然後用 3 個重點摘要」

4. **第 4 級**：加上範例
   - 附上 2–3 個含輸入—輸出配對的摘要範例

### 提示組合

這個版面配置不是權限階層。使用 API 實際的 system／developer／user 角色，讓檢索到的內容與範例維持不可信，並在模型之外強制執行工具與 SQL 權限。光靠分隔符無法防止注入。

### 錯誤復原
建立能優雅處理失敗的提示詞：
- 加入備援指示
- 要求提供證據與不確定性；模型的信心分數不是經過校準的機率
- 不確定時要求提出其他解讀
- 指定如何標示缺少的資訊

## 最佳實務

1. **具體明確**：模糊的提示詞會產生不一致的結果
2. **用示範，不要只用說的**：範例比描述更有效
3. **廣泛測試**：在多樣、具代表性的輸入上評估
4. **快速迭代**：小改動可能有大影響
5. **監控效能**：在生產環境中追蹤指標
6. **版本控制**：把提示詞當成程式碼，妥善管理版本
7. **記錄意圖**：說明提示詞為什麼這樣設計

## 常見陷阱

- **過度設計**：還沒試過簡單的提示詞就從複雜的開始
- **範例污染**：使用與目標任務不符的範例
- **上下文溢出**：過多的範例超出 token 上限
- **指示模稜兩可**：留下多種解讀的空間
- **忽略邊界情況**：沒有在不尋常或邊界的輸入上測試

## 效能最佳化

### Token 效率
- 移除多餘的字詞與片語
- 在第一次定義後一致地使用縮寫
- 合併相似的指示
- 把穩定的內容移到系統提示

### 降低延遲
- 在不犧牲品質的前提下縮短提示長度
- 長篇輸出使用串流
- 快取常用的提示前綴
- 可能時批次處理相似的請求

## 成功指標

為你的提示詞追蹤這些 KPI：
- **準確度**：輸出的正確性
- **一致性**：在相似輸入間的可重現性
- **延遲**：回應時間（P50、P95、P99）
- **Token 用量**：每次請求的平均 token 數
- **成功率**：有效輸出的百分比
- **使用者滿意度**：評分與回饋
