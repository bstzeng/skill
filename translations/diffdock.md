# DiffDock：以擴散模型進行分子對接

## 概覽

DiffDock 是一個以擴散模型為基礎的深度學習分子對接工具，用來預測小分子配體與蛋白質標靶的 3D 結合姿態。它代表了計算對接的最先進水準，對以結構為基礎的藥物探索與化學生物學至關重要。

**核心能力：**
- 以深度學習高準確度地預測配體結合姿態
- 支援蛋白質結構（PDB 檔）或序列（透過 ESMFold）
- 處理單一複合物或批次虛擬篩選活動
- 產生信心分數以評估預測的可靠性
- 處理多樣的配體輸入（SMILES、SDF、MOL2）

**關鍵區別：** DiffDock 預測的是 **結合姿態**（3D 結構）與 **信心**（預測的確定程度），「不是」結合親和力（ΔG、Kd）。評估親和力時，一律搭配評分函數（GNINA、MM/GBSA）。

## 何時使用本技能

在以下情況應使用本技能：

- 「把這個配體對接到蛋白質」或「預測結合姿態」
- 「執行分子對接」或「進行蛋白質—配體對接」
- 「虛擬篩選」或「篩選化合物庫」
- 「這個分子結合在哪裡？」或「預測結合位點」
- 以結構為基礎的藥物設計或先導化合物最佳化任務
- 涉及 PDB 檔 + SMILES 字串或配體結構的任務
- 批次對接多組蛋白質—配體配對

## 解讀信心分數

**理解分數：**

| 分數範圍 | 信心等級 | 解讀 |
|------------|------------------|----------------|
| **> 0** | 高 | 強的預測，很可能準確 |
| **-1.5 到 0** | 中 | 合理的預測，要仔細驗證 |
| **< -1.5** | 低 | 不確定的預測，需要驗證 |

**關鍵注意事項：**
1. **信心 ≠ 親和力**：高信心代表模型對結構有把握，「不是」代表結合很強
2. **情境很重要**：以下情況要調整預期：
   - 大型配體（>500 Da）：預期信心較低
   - 多條蛋白質鏈：可能降低信心
   - 新穎的蛋白質家族：可能表現不佳
3. **多個樣本**：檢視前 3–5 個預測，尋找共識

**詳細指引：** 使用 Read 工具閱讀 `references/confidence_and_limitations.md`

### 需要調整的關鍵參數

**取樣密度：**
- `samples_per_complex: 10` → 困難的情況增加到 20–40
- 樣本越多＝涵蓋越好，但執行時間越長

**推論步數：**
- `inference_steps: 20` → 增加到 25–30 以提高準確度
- 步數越多＝品質可能越好，但越慢

**溫度參數（控制多樣性）：**
- `temp_sampling_tor: 7.04` → 柔性配體調高（8–10）
- `temp_sampling_tor: 7.04` → 剛性配體調低（5–6）
- 溫度越高＝姿態越多樣

**範本中可用的預設組合：**
1. 高準確度：更多樣本與步數、較低溫度
2. 快速篩選：較少樣本、較快
3. 柔性配體：提高扭轉溫度
4. 剛性配體：降低扭轉溫度

## 限制與範圍

**DiffDock 的設計適用於：**
- 小分子配體（通常 100–1000 Da）
- 類藥性有機化合物
- 小型胜肽（<20 個殘基）
- 單鏈或多鏈蛋白質

**DiffDock 的設計不適用於：**
- 大型生物分子（蛋白質—蛋白質對接）→ 使用 DiffDock-PP 或 AlphaFold-Multimer
- 大型胜肽（>20 個殘基）→ 使用其他方法
- 共價對接 → 使用專門的共價對接工具
- 結合親和力預測 → 搭配評分函數
- 膜蛋白 → 沒有特別訓練，謹慎使用

**完整的限制：** 使用 Read 工具閱讀 `references/confidence_and_limitations.md`

## 疑難排解

### 常見問題

**問題：所有預測的信心分數都很低**
- 原因：大型／不尋常的配體、結合位點不明確、蛋白質柔性
- 解法：增加 `samples_per_complex`（20–40）、嘗試集成對接、驗證蛋白質結構

**問題：記憶體不足錯誤**
- 原因：GPU 記憶體不足以應付批次大小
- 解法：降低為 `--batch_size 2`，或一次處理較少的複合物

**問題：效能緩慢**
- 原因：在 CPU 而不是 GPU 上執行
- 解法：用 `python -c "import torch; print(torch.cuda.is_available())"` 確認 CUDA，使用 GPU

**問題：不合理的結合姿態**
- 原因：蛋白質準備不佳、配體太大、結合位點錯誤
- 解法：檢查蛋白質是否缺少殘基、移除遠處的水分子、考慮指定結合位點

**問題：「Module not found」錯誤**
- 原因：缺少相依套件或環境錯誤
- 解法：執行 `python scripts/setup_check.py` 進行診斷

### 效能最佳化

**為了最佳結果：**
1. 使用 GPU（實際使用時不可或缺）
2. 對重複使用的蛋白質預先計算 ESM 嵌入
3. 把多個複合物一起批次處理
4. 從預設參數開始，需要時再調整
5. 驗證蛋白質結構（補齊缺少的殘基）
6. 配體使用標準化（canonical）的 SMILES

## 最佳實務

1. 開始大型工作前，**一律用 `setup_check.py` 確認環境**
2. **用 `prepare_batch_csv.py` 驗證批次 CSV**，及早抓到錯誤
3. **從預設值開始**，再依系統的特定需求調整參數
4. **產生多個樣本**（10–40）以得到穩健的預測
5. 進行下游分析前，**目視檢查** 最佳的姿態
6. **搭配評分** 函數評估親和力
7. **用信心分數** 做初步排序，而不是最終決策
8. 虛擬篩選活動 **預先計算嵌入**
9. **記錄使用的參數** 以便重現
10. 可能時以實驗 **驗證結果**
