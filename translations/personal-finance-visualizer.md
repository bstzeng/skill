# 個人財務視覺化

準備一份對帳後的資料集，並以本機報表呈現。回應與報表使用使用者的語言（`en` 或 `zh-CN`）；若使用者明確要求某種語言，就遵照。準備輸入之前先閱讀 [references/schema.md](references/schema.md)，擷取、對帳與交付則參考 [references/workflow.md](references/workflow.md)。

## 保留報表介面

透過 `scripts/report.py` 渲染內附的 `assets/report.html`、`report.css`、`app.js` 與 `engine.js`。這些檔案是持續維護的介面，不是讓你另外產生新儀表板的建議。不要換成不同的設計、指標卡、分頁或圖表函式庫。預設是深色的環圈報表：四個檢視按鈕靠標題右側對齊；期間控制附日曆彈出視窗（週一開始的日／週選擇、月與年的格狀選擇、日期限制在資料涵蓋範圍內、鍵盤導覽與減少動態）；三個主要支出環圈、三個次要環圈、商家明細環圈、時間軸與收合的明細。收入使用兩個主要與三個次要環圈，轉帳使用兩個環圈與三個指標，總覽使用三個指標。圖例最多顯示六列，內部可捲動並有邊緣淡出。保留圓角的列回饋，以及指標與鍵盤都能觸發的圖表提示。支出、收入與轉帳的時間軸預設為漸層面積圖，支援依實際日期拖曳檢視、有界的平滑化、可中斷的期間切換、鍵盤下鑽與減少動態。保留有標籤、可水平捲動的長條圖作為可選的替代樣式。面積圖的提示只顯示實際觀測值，絕不顯示內插的金額。以響應式格狀排列卡片。寬度 700px 以下時，每列維持兩張環圈／指標卡，等比縮放為 0.5，間距 12px；時間軸與明細維持全寬。保留能感知縮放的拖曳座標與移動轉場。允許在目前檢視中拖曳標題、以鍵盤重新排序、取消，以及每個檢視各自重設。保留預設的日常商家明細卡，不加商家群組選擇器，也不顯示拖曳說明文字。讓日／週／月／年控制在頁面上置中，與旁邊的期間標籤和日期導覽各自獨立。檢視、期間與圖表樣式切換都使用同一個可中斷的滑動指示器，只對受影響的可見內容做短暫的不透明度／位置轉場。佈景主題切換使用短暫的顏色轉場。減少動態時停用非必要的動畫。收合的交易表格與每月摘要在展開時才建立，重用數字格式器，並避免在圖表點的動畫迴圈中重複格式化。把底部的摘要、交易表格、全部月份總覽、退款與備註歸入同一個收合的「更多資訊」區塊，並保留各自內部的展開控制。在資訊控制上顯示卡片說明。切換期間時讓卡片表面持續可見。保留可中斷的環圈與中心／圖例金額內插，圖例列由上而下顯現，最終數值精確。除非使用者要求重新設計視覺，否則沿用既有的配色與版面。對展開面板、對話框、選單與小型控制回饋做動畫但不阻擋輸入；尊重減少動態設定，並延後畫面外的動畫。只有在使用者要求時才變更設計。

## 資料邊界

- 只讀取這次任務獲得授權的紀錄。不要蒐集憑證、連結銀行帳戶、付款、轉帳或修改訂閱。
- 預設把資料保留在程序記憶體中。不要在任務中順帶建立正規化輸入檔、日誌、截圖、記憶條目或快取的財務摘要。絕不把真實紀錄放進本技能、它的 Git repository、範例或公開 issue。
- 使用 loopback 記憶體伺服器交付。只有在使用者要求儲存／匯出時，才匯出本機 HTML 檔案，並存到使用者選擇的本機位置。匯出檔包含交易明細。不要發布或上傳個人報表。
- 使用者重新排列卡片後，只在本機瀏覽器儲存空間中儲存不透明的卡片識別碼與其順序，每個檢視分開儲存。絕不在那裡儲存交易資料、金額、商家文字或帳戶識別碼。版面在相同瀏覽器來源重新整理後會保留；如果無法使用儲存空間，就保留頁面內的順序並顯示這個限制。
- 渲染器沒有遙測或遠端資源。獨立的報表不會發出任何請求。明確設定的預算整合只能透過同源的 `/api/budget` 端點讀取與儲存設定；絕不設定外部目的地。代理宿主可能會依其自身設定保留提示詞、工具呼叫或提供的檔案。相關時簡短說明這點；雲端代理讀取資料並不是完全離線的處理。瀏覽器歷史紀錄／快取與明確的匯出，也不在完全清除的承諾範圍內。
- 處理財務紀錄時絕不自動檢查更新。`scripts/check_update.py` 是一個明確、獨立的公開版本查詢；它不會接收財務輸入。

## 準備與驗證

對於很長的商家名稱，可以依結構定義提供選用的 `merchantDisplayNames`：只在顯示時縮短明確辨識的名稱，在明細中保留原始描述，且絕不透過顯示標籤改變分組或分類。

使用正規化的 JSON 或 CSV。原始的銀行 CSV 需要明確的欄位、正負號與日期對應。PDF 擷取使用代理可用且經授權的工具；本技能不包含通用的對帳單解析器。如果無法擷取，就說明限制並請使用者提供可存取的匯出檔。

保留來源的日期與金額。渲染前確認來源涵蓋範圍、重複的證據、幣別與正負號。用途尚未確立的不明入帳，一律視為轉帳。只有在確認後才套用個人分攤、全額退款配對與轉帳沖銷；絕不只依名稱、金額或日期配對。不確定的交易要透過下方的確認步驟解決；備註是在那一步之後揭露剩餘的限制，而不是用來取代詢問。讓涵蓋範圍的缺口保持可見。

報表把以銀行日期計的現金流動與個人支出分開。帳戶之間的內部移動不算外部現金流動。分攤只影響支出。已確認的待入帳購買在入帳之前計入支出與預算，但不計入現金流動。已確認的全額退款會在購買的期間抵銷支出；現金流動則保留實際的銀行日期。部分退款與未配對的項目請見結構定義。

## 產出最終圖表前先詢問

對每一位使用者，在產生或更新最終圖表之前，先檢查是否有尚未釐清的交易。先閱讀可用的來源證據與使用者既有的確認。當某筆交易的用途、類別、帳戶歸屬、個人分攤、收入／轉帳的處理方式，或退款／還款關係仍不確定時，在對話中以簡潔的確認表列出，並請使用者釐清具體缺少的事實。包含日期、帳戶別名、商家／描述、帶正負號的金額與幣別、哪裡不確定，以及要回答的問題。任何提議的分類都標示為建議，而不是事實。

把要求範圍內尚未釐清的項目整批列出。不要默默猜測、把它們藏在報表備註裡然後繼續，或把沒有回應解讀為同意。等待期間可以繼續進行獨立的擷取與對帳，但在定稿受影響的圖表之前要等到回答。如果使用者明確要求暫時預覽，或選擇讓項目維持未釐清，就尊重這個選擇，並清楚標示這些項目及其對總額的影響；不要把它們呈現為已確認。

把確認套用到所辨識的交易，而不改變銀行日期、金額或來源描述。重新計算並驗證受影響的表格與圖表。在已確認的範圍內重用先前的回答，包括明確選擇讓某個項目維持待定；不要一再詢問同樣的問題，也不要把單一筆購買推廣成對該商家所有付款的規則。詳細流程與表格格式在 [references/workflow.md](references/workflow.md#confirm-uncertain-transactions)。

## 選用的每日可用額度

被要求時，提供 `references/schema.md` 中描述的 `budget` 輸入。額外的「每日可用額度」檢視使用日曆月的預算、每日上限與已確認的個人支出。它會把當月剩餘的額度重新分配到剩下的天數，在下個月重設，且不把收入或內部轉帳當作額外預算。歷史類別占比使用最多前三個完整月份的日常支出；使用者可以調整這些參考占比。占比以一張圓餅圖呈現；未分類的類別不列入，其餘重新縮放為 100%，但它們的支出仍會計入。在今天的可用額度旁邊，檢視會以金額與百分比顯示相較於昨天開始時可用額度的變化，使用目前的設定。固定開銷的每日等值用來解釋支出，不會被重複扣除。

清楚區分預算日期與來源的截止日期。缺少當月的涵蓋範圍，或紀錄早於昨天，會使今天的可用額度無法計算。不要推斷未來的帳單。只有在使用者確認某筆待入帳費用是真實的購買後才將其納入，並讓它的待入帳狀態保持可見。在使用不確定的分類之前，維持既有的確認要求。

獨立報表只在目前頁面的記憶體中套用預算編輯；不得把預算數值存進 localStorage。持久的跨裝置編輯需要一個明確授權、經過認證、以私有儲存為後盾的同源預算端點。只傳送設定，不傳送交易紀錄。準確地顯示載入中、儲存失敗與同時編輯的狀態；絕不把未確認的儲存視為成功。主機的授權與本技能預設不發布的規則維持不變。
