## 關鍵模式

### 漸進式揭露

從簡單的提示開始，只在需要時增加複雜度：

1. **第 1 級**：直接指示
   - 「摘要這篇文章」

2. **第 2 級**：加上限制
   - 「用 3 個重點摘要這篇文章，聚焦在主要發現」

3. **第 3 級**：加上推理
   - 「閱讀這篇文章，找出主要發現，然後用 3 個重點摘要」

4. **第 4 級**：加上範例
   - 附上 2–3 個含輸入—輸出配對的摘要範例

### 錯誤復原

建立能優雅處理失敗的提示：

- 加入備援指示
- 要求信心分數
- 不確定時要求提出其他解讀
- 指定如何標示缺少的資訊

## 最佳實務

1. **具體明確**：模糊的提示會產生不一致的結果
2. **用示範，不要只用說的**：範例比描述更有效
3. **廣泛測試**：在多樣、具代表性的輸入上評估
4. **快速迭代**：小改動可能有大影響
5. **監控效能**：在生產環境中追蹤指標
6. **版本控制**：把提示當成程式碼，妥善管理版本
7. **記錄意圖**：說明提示為什麼這樣設計

## 常見陷阱

- **過度設計**：還沒試過簡單的提示就從複雜的開始
- **範例污染**：使用與目標任務不符的範例
- **上下文溢出**：過多的範例超出 token 上限
- **指示模稜兩可**：留下多種解讀的空間
- **忽略邊界情況**：沒有在不尋常或邊界的輸入上測試

# 代理提示的最佳實務

以 Anthropic 官方的代理提示最佳實務為基礎。

## 核心原則

### 上下文視窗

「上下文視窗」指的是語言模型在產生新文字時，能回顧並參照的全部文字量，再加上它產生的新文字。這與語言模型訓練所用的大量資料不同，而是代表模型的「工作記憶」。較大的上下文視窗讓模型能理解並回應更複雜、更長的提示，而較小的上下文視窗可能會限制模型處理較長提示或在長對話中保持連貫的能力。

- 漸進的 token 累積：隨著對話一輪輪進行，每則使用者訊息與助理回應都會累積在上下文視窗中。先前的輪次會完整保留。
- 線性成長模式：上下文的使用量隨每一輪線性成長，先前的輪次會完整保留。
- 20 萬 token 容量：可用的上下文視窗總量（200,000 個 token）代表儲存對話歷史與讓 Claude 產生新輸出的最大容量。
- 輸入—輸出流程：每一輪包含：
  - 輸入階段：包含所有先前的對話歷史，加上目前的使用者訊息
  - 輸出階段：產生一段文字回應，成為未來輸入的一部分

### 精簡是關鍵

上下文視窗是公共資源。你的提示、指令、技能，與 Claude 需要知道的所有其他東西共用上下文視窗，包括：

- 系統提示
- 對話歷史
- 其他指令、技能、hook、中繼資料
- 你實際的請求

**預設假設**：Claude 已經非常聰明

只加入 Claude 還不知道的脈絡。質疑每一則資訊：

- 「Claude 真的需要這個解釋嗎？」
- 「我能假設 Claude 已經知道這個嗎？」
- 「這一段值得它的 token 成本嗎？」

### 5. 一體感

**是什麼：** 共同的身分、「我們」的感覺、群體歸屬。

**在提示中如何運作：**

- 協作的語言：「我們的程式碼庫」「我們是同事」

- 協作的工作流程
- 建立團隊文化
- 非階層式的實務

### 6. 互惠

**是什麼：** 回報所得好處的義務感。

**如何運作：**

- 節制地使用——可能讓人覺得被操弄
- 在提示中很少需要

**何時避免：**

- 幾乎總是（其他原則更有效）

### 7. 喜好

**是什麼：** 偏好與我們喜歡的人合作。

**如何運作：**

- **不要用來促使遵從**
- 與誠實回饋的文化衝突
- 會造成諂媚

**何時避免：**

- 用於強制紀律時一律避免

## 依提示類型的原則組合

| 提示類型 | 使用 | 避免 |
|------------|-----|-------|
| 強制紀律 | 權威 + 承諾 + 社會認同 | 喜好、互惠 |
| 指引／技巧 | 適度的權威 + 一體感 | 強烈的權威 |
| 協作 | 一體感 + 承諾 | 權威、喜好 |
| 參考資料 | 只需清晰 | 所有說服手法 |

## 為什麼有效：背後的心理學

**明確的界線規則能減少自我合理化：**

- 「你必須」消除決策疲勞
- 絕對的語言消除「這算不算例外？」的疑問
- 明確的反合理化對策能堵住特定的漏洞

**執行意圖會產生自動化的行為：**

- 清楚的觸發條件 + 必要的動作 = 自動執行
- 「當 X 時，做 Y」比「一般來說做 Y」更有效
- 降低遵從的認知負擔

**LLM 是類人的：**

- 以包含這些模式的人類文字訓練
- 在訓練資料中，權威語言常出現在遵從之前
- 承諾序列（陳述 → 行動）經常被示範
- 社會認同模式（每個人都做 X）建立規範

## 合乎倫理的使用

**正當的：**

- 確保關鍵的做法被遵循
- 建立有效的文件
- 預防可預見的失敗

**不正當的：**

- 為個人利益而操弄
- 製造虛假的急迫感
- 以罪惡感促使遵從

**檢驗方式：** 如果使用者完全理解這個技巧，它是否仍符合使用者的真正利益？

## 速查

設計提示時，問自己：

1. **它是什麼類型？**（紀律 vs. 指引 vs. 參考資料）
2. **我想改變什麼行為？**
3. **適用哪些原則？**（紀律類通常是權威 + 承諾）
4. **我是否組合了太多？**（不要七種全用）
5. **這合乎倫理嗎？**（是否符合使用者的真正利益？）
