# 喬木大學生簡歷

把零散、真實的學生經歷整理成可投遞、可編輯、可複核的 HTML 與 PDF 簡歷。內容可信優先於修辭，崗位相關性優先於資訊堆疊。

## 使用邊界

- 適用：在校生、應屆生、畢業三年內的早期職業求職者；預設兼顧中文校招與技術崗位。
- 不適用：學術申請 CV、資深高管履歷、作品集網站、求職信、代投或招聘平臺賬號操作。
- 不承諾“透過率”“邀約率”或 ATS 分數；只能報告實際做過的結構、關鍵詞、文字提取和檔案檢查。
- 不得虛構公司、專案、職責、技術棧、獎項、使用者量或效能數字。所有可驗證陳述必須進入事實證據鏈。

## 四種能力路由

先判斷使用者已有材料與明確意圖，不把所有請求都拉回同一套採訪：

| 入口 | 第一動作 | 完成條件 |
|---|---|---|
| 從 0 問答寫簡歷 | 讀取 [對話式訪談與採集](references/intake-and-interview.md)，從目標崗位或最強經歷開始，每輪只問一個問題 | 事實賬本透過訪談門禁並獲得本人確認，再生成預設單主題 PDF |
| 提供舊簡歷最佳化 | 先提取並複述已有事實，不重複詢問；使用者要改內容時，只追問會改變表達的缺口 | 內容最佳化走完整證據門禁；只改排版走“排版快速路徑” |
| 提供 JD 針對性定製 | 同時抽取 JD 必備條件、加分項與職責，建立 `JD 要求 → 已有證據 / 缺口 → 簡歷位置` 對映 | 只寫有證據的關鍵詞；缺口明確標記，不把 JD 要求偽裝成候選人技能 |
| 一次生成多種風格 | 固定同一份已確認事實，直接使用 `--all-themes` 生成六套核心主題 | 六份 HTML/PDF、清單與批次驗證全部透過，並逐頁檢視 |

**排版快速路徑**：僅當使用者明確要求“內容不改，只美化/重排/換模板”時使用。執行 `extract_resume.py`，展示提取到的姓名、教育、經歷、技能和時間線摘要，請使用者一次確認；隨後以 `source_resume` 標記原文事實，執行 `validate_resume.py` 並渲染。不要強迫使用者補兩項新證據，不做未經請求的內容改寫；若原文存在影響投遞的矛盾、佔位符或缺失聯絡方式，只問一個阻斷問題，無法確認的內容省略或標為草稿。

## 精簡工作流程

1. **建立工作目錄**：在使用者工作區新建獨立輸出目錄；保留原始檔案，不覆蓋、不改名、不上傳外部服務。
2. **按四種能力路由選擇入口並啟動對話**：
   - 有舊簡歷：執行 `scripts/extract_resume.py` 提取文字，並保留來源路徑；掃描件無文字時，明確徵得同意後才做 OCR。
   - 無舊簡歷、資訊不足或使用者要求採訪：必須讀取 [對話式訪談與採集](references/intake-and-interview.md)，使用一問一答模式。每輪只問一個核心問題，並附上可被使用者糾正的當前判斷；不要發巨型問卷。
   - 有崗位 JD：同時提取必備條件、加分項、工作內容、關鍵詞和不匹配項；沒有 JD 時按目標崗位族生成通用版。
3. **深挖並維護事實賬本**：除純排版快速路徑外，優先沿最強經歷逐層追問情境、個人職責、關鍵行動、結果、證據和麵試可解釋性；每 2–3 輪用不超過 5 條複述已確認事實與剩餘缺口。把過程寫入本地 `interview-ledger.json`，把可公開成果標註 `evidence_type`。遵循 [真實性與證據](references/content-integrity.md)。
4. **確定策略**：必須讀取 [簡歷寫作與版式最佳實踐](references/best-practices.md) 與 [內容與崗位策略](references/resume-strategy.md)，建立 `JD 要求 → 證據 → 簡歷位置` 對映；選擇目標崗位、語言和一頁/兩頁上限。按 [六主題系統](references/style-system.md) 選擇核心主題，並遵循 [字型與印刷排版系統](references/typography-system.md)。使用者提到 ResumeCollection、模板編號或要看更多簡潔方案時，讀取 [ResumeCollection 簡潔參考目錄](references/resume-collection-catalog.md)，選擇單個重構預設或六預設對比輸出。
5. **透過生成門禁**：從 0 建立、內容最佳化或 JD 定製時，執行 `python3 scripts/assess_interview.py interview-ledger.json`；目標崗位、基礎資訊、教育、兩項可用證據、技能證據鏈、關鍵疑點和本人確認全部透過後，才進入最終生成。純排版快速路徑改為“來源提取成功、事實摘要獲確認、`source_resume` 證據型別完整、`validate_resume.py` 透過”四項門禁。使用者中途要求停止時，交付事實摘要與精確缺口；除非對應門禁透過，否則只可生成明確標註的草稿 JSON/HTML，不把 PDF 偽裝成最終版。
6. **確認並起草資料檔案**：先向使用者展示“目標崗位 / 核心經歷 / 可用數字 / 技能 / 捨棄項 / 仍有疑點”的簡短事實摘要，獲得明確確認。再按 [資料契約](references/data-contract.md) 寫出 `resume-data.json`；需要估算時必須保守、顯式標記並由學生確認。
7. **內容審校**：按 A-C-R-E 檢查每條 bullet 的動作、情境/範圍、結果與證據；檢查時間線、個人/團隊邊界、技能與專案對應關係、數字證據、拼寫、連結、章節順序和崗位關鍵詞自然度。執行 `validate_resume.py` 後逐條處理弱職責詞、過長 bullet、孤立技能和結果訊號不足的警告；不要為了“每條都有數字”而製造數字。
8. **渲染**：預設只生成一份最合適的簡歷：

   ```bash
   python3 scripts/render_resume.py resume-data.json --theme tech --output-dir output
   ```

   預設根據崗位選擇一個核心主題，並根據真實內容量自動選擇 `sparse / balanced / dense` 密度，生成一份 HTML 與文字型 PDF；使用者明確要求對比時，才使用 `--all-themes` 或參考預設批次命令。邊框宣告只允許頁頭和章節標題使用 `border-bottom` 分割線；禁止 `border-radius`、閉合邊框、頂邊、側邊線、側邊欄和卡片輪廓。無輪廓、無圓角的淺色頁頭 wash 或完整橫向章節色帶允許使用。中文 PDF 必須實際嵌入主題宣告的本機字型；Kami 主題要求 TsangerJinKai02 W04，W05 僅在已安裝時用於標題。

   使用者選擇 ResumeCollection 參考預設時使用：

   ```bash
   python3 scripts/render_resume.py resume-data.json --reference-style rc-071 --output-dir output
   # 或一次生成六個參考預設
   python3 scripts/render_resume.py resume-data.json --all-reference-styles --output-dir output
   ```
9. **驗收**：單主題先執行 `validate_resume.py --theme <id>`；批次比較才執行：

   ```bash
   python3 scripts/validate_style_set.py resume-data.json output/resume_六風格清單.json --output output/validation-all.json
   ```

   單主題輸出仍可使用 `validate_resume.py --theme <id>`。再按 [視覺與 PDF 驗收](references/visual-and-pdf.md) 將每頁轉為圖片並逐頁檢視；確認無溢位、孤行、斷裂、重疊、異常空白，且 `pdftotext` 能讀出姓名、聯絡方式和標準章節。
10. **交付**：預設提供 1 份最終 PDF、對應 HTML、`resume-data.json` 和驗證報告；從 0、內容最佳化或 JD 定製另附 `interview-ledger.json`，純排版快速路徑另附來源提取文字。只有使用者明確要求比較時才交付多主題檔案。用不超過 5 條說明定位、核心內容取捨與仍需本人確認的事實。

## 路由規則

- 預設一頁；先刪除弱資訊，當真實且崗位相關的實習/專案仍無法在不低於 9.1pt 正文的情況下清晰呈現時，才擴充套件到兩頁。
- 未指定風格時由內容與崗位決定一個預設主題並生成一份；明確要求對比時才生成六套，明確指定主題時只生成該主題。
- 使用者說“一次生成多種/不同風格/都生成看看”時，預設一次生成六套核心主題，不先要求挑選單一模板；所有版本必須共用同一份事實資料。
- 使用者只要求美化或重排舊簡歷時，走排版快速路徑，保留原事實與措辭邊界；不得把“美化”自動擴大為虛構量化結果或重寫職業經歷。
- 使用者提供 JD 時，先給出要求—證據—缺口摘要，再按證據重排與改寫；沒有證據的 JD 關鍵詞不得進入技能欄或經歷 bullet。
- ResumeCollection 參考預設是顯式選項，不混入預設核心六主題；指定編號時只生成該預設，要求比較時才生成全部六個參考預設。
- 參考預設只吸收排版骨架；禁止複製或打包上游 DOCX、預覽圖、照片、圖示和字型。
- 六主題都是單欄與標準章節，不用“兩欄更好看”作為犧牲 ATS 文字順序的理由。
- 目標崗位不明確時，先從經歷證據給出 1 個預設方向和最多 2 個備選；只有選擇會顯著改變內容時才追問。
- 對話訪談一次只問一個核心問題；問題必須附當前判斷或推薦答案，允許學生直接糾正。不要在一條訊息裡批次索取整份簡歷欄位。
- 沿一項經歷深挖到“個人貢獻—行動—結果—證據—可解釋性”閉環後，再切換下一項；使用者已主動覆蓋的資訊不得重複詢問。
- “隨便”“你看著辦”“應該差不多”不等於事實確認；先給出具體複述並要求確認。使用者可以隨時說“跳過”“不知道”“停止採訪”。
- 技術崗位優先展示專案、技術決策、個人貢獻和可解釋的結果；非技術崗位把“技能”替換為崗位相關能力與工具。
- 關鍵詞只能在事實支援時加入；JD 提到的技能不能因為“匹配”而寫進候選人簡歷。
- 弱經歷優先挖掘範圍、複雜度、約束、協作和完成度，不強行包裝成商業影響。
- 輸出中的聯絡方式和個人連結屬於隱私資料；不寫入報告、示例、日誌或外部服務。

## 門禁階梯

- 訪談門禁：從 0、內容最佳化或 JD 定製時，`assess_interview.py` 必須確認目標、基礎資訊、教育、至少兩項崗位相關證據、技能證據鏈、零阻斷疑點和明確本人確認；未透過時只能交付事實摘要或草稿。
- 排版快速路徑門禁：舊簡歷提取成功、事實摘要經使用者確認、每條經歷帶 `source_resume` 證據型別、`validate_resume.py` 透過；不要求使用者為了換版式重新完成兩項深度訪談。
- 內容門禁：`validate_resume.py` 必須確認關鍵欄位、證據型別、時間線、連結、章節順序和佔位符；弱職責詞、孤立技能、過長 bullet 與結果訊號不足必須修復或給出事實依據。純排版快速路徑若因使用者明確禁止改文案而保留來源警告，必須在交付中說明“只最佳化排版，未完成內容最佳化”，不得靜默改寫或聲稱內容已最佳化。
- 渲染門禁：HTML 與 PDF 必須由同一份 JSON 生成；至少有一條 `border-bottom` 分割線，`border-radius` 與閉合/頂部/側邊邊框宣告必須為 0。
- 主題門禁：核心主題 ID、參考預設 ID、核心色、目標字型與 HTML 的 `data-theme` / `data-reference-style` 必須一致；批次輸出必須正好包含六套清單條目。
- 排版門禁：HTML 必須使用 1.5 排版系統與自適應密度標記，宣告目標中文字型和拉丁字型層；px、italic、連結色塊與技術名詞錯誤大小寫必須為 0。
- PDF 門禁：A4、1–2 頁、未加密、文字可提取、包含關鍵欄位；中文用 `pdffonts` 證明主題目標字型已實際嵌入，其中 Kami 必須為 TsangerJinKai02。
- 視覺門禁：每頁實際檢視，無裁切、重疊、斷裂、孤行或異常空白後才能交付。

## 輸出契約

- 對話：自然聊天式一問一答；每輪 1 個核心問題，附當前判斷；定期複述已確認事實與下一缺口。
- 事實賬本：從 0、內容最佳化或 JD 定製時，本地 `interview-ledger.json` 儲存已確認事實、疑點、證據關聯和確認狀態；純排版快速路徑可以不建訪談賬本，但必須保留本地提取文字與一次事實確認。兩者都不上傳外部服務。
- PDF：預設一套；A4、1–2 頁、文字可選擇與提取、無密碼、無遠端字型/圖片依賴。批次比較僅在使用者明確要求時生成。
- HTML：與最終 PDF 同源、可本地修改、列印樣式固定。
- JSON：儲存內容與證據型別，不把私密來源備註渲染進公開簡歷。
- 六風格清單：記錄主題 ID、中文名、適用場景與交付路徑。
- 參考風格清單：選擇批次參考預設時，額外記錄預設 ID、基礎主題、來源編號、來源連結與交付路徑。
- 驗證報告：逐主題記錄結構、事實、色彩、字型、頁數、文字提取與檔案檢查；審美結論必須來自實際逐頁檢視。
