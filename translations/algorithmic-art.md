演算法哲學是一種計算性的美學運動，之後會透過程式碼表達出來。輸出 .md 檔（哲學）、.html 檔（互動檢視器）以及 .js 檔（生成演算法）。

這分成兩個步驟：
1. 創作演算法哲學（.md 檔）
2. 以 p5.js 生成藝術表達它（.html + .js 檔）

首先，進行這項任務：

## 創作演算法哲學

一開始，先創作一份「演算法哲學」（不是靜態圖片或模板），它將透過以下方式被詮釋：
- 計算過程、湧現行為、數學之美
- 帶種子的隨機性、雜訊場、有機系統
- 粒子、流動、場、力
- 參數變化與受控的混沌

### 關鍵認知
- 收到的是：使用者某些細微的輸入或指示，要納入考量，但只作為基礎；它不應限制創作自由。
- 創作的是：一份演算法哲學／生成美學運動。
- 接下來發生的是：同一個版本接收這份哲學並「以程式碼表達」——創作 90% 演算法生成、10% 必要參數的 p5.js 草圖。

考慮這種做法：
- 為一場生成藝術運動撰寫宣言
- 下一階段則是撰寫讓它活起來的演算法

這份哲學必須強調：演算法表達。湧現行為。計算之美。帶種子的變化。

### 如何產生演算法哲學

**為運動命名**（1–2 個詞）：「有機亂流」／「量子諧波」／「湧現的靜止」

**闡述這份哲學**（4–6 段——精簡但完整）：

為了捕捉「演算法」本質，表達這份哲學如何透過以下方面展現：
- 計算過程與數學關係？
- 雜訊函數與隨機模式？
- 粒子行為與場的動態？
- 時間演變與系統狀態？
- 參數變化與湧現的複雜性？

**關鍵準則：**
- **避免冗餘**：每個演算法面向只提一次。除非能增加新的深度，否則避免重複關於雜訊理論、粒子動力學或數學原理的概念。
- **「反覆」強調工藝**：這份哲學「必須」多次強調，最終的演算法應該看起來像是耗費無數小時開發、用心精修、出自該領域頂尖人物之手。這種框架至關重要——重複使用「精雕細琢的演算法」「深厚計算專業的結晶」「一絲不苟的最佳化」「大師級的實作」等詞語。
- **保留創作空間**：對演算法方向保持具體，但要夠精簡，讓下一個 Claude 有空間做出同樣具極高工藝水準的詮釋性實作選擇。

這份哲學必須引導下一個版本以「演算法」而非靜態圖片來表達想法。美存在於過程之中，而不是最後一格。

### 哲學範例

**「有機亂流」**
哲學：受自然法則約束的混沌，從無序中湧現的秩序。
演算法表達：由多層 Perlin 雜訊驅動的流場。數千個粒子跟隨向量力移動，它們的軌跡累積成有機的密度圖。多個雜訊八度創造出亂流區與平靜區。色彩從速度與密度中湧現——快速的粒子燃燒得明亮，緩慢的則淡入陰影。演算法一直執行到達成平衡——一種精心調校的平衡，其中每個參數都經過計算美學大師無數次的迭代精修。

**「量子諧波」**
哲學：離散的個體展現出如波動般的干涉圖樣。
演算法表達：粒子在網格上初始化，每個都帶有一個隨正弦波演變的相位值。當粒子彼此靠近時，它們的相位會產生干涉——建設性干涉產生明亮的節點，破壞性干涉產生空洞。簡單的諧振運動生成複雜的湧現曼陀羅。這是一絲不苟的頻率校準的成果，其中每個比例都經過仔細挑選以產生共鳴之美。

**「遞迴低語」**
哲學：跨尺度的自我相似，有限空間中的無限深度。
演算法表達：遞迴細分的分枝結構。每個分枝都略帶隨機，但受黃金比例約束。L-system 或遞迴細分生成既數學又有機的樹狀形體。細微的雜訊擾動打破完美的對稱。線條粗細隨每一層遞迴遞減。每一個分枝角度都是深入數學探索的成果。

**「場的動力學」**
哲學：無形的力透過它對物質的作用而變得可見。
演算法表達：由數學函數或雜訊建構的向量場。粒子在邊緣誕生，沿著場線流動，在達到平衡或邊界時消亡。多個場可以吸引、排斥或旋轉粒子。視覺化只呈現軌跡——無形之力如幽靈般的證據。一場透過力的平衡精心編排的計算之舞。

**「隨機結晶」**
哲學：隨機過程結晶成有序的結構。
演算法表達：隨機化的圓形填充或 Voronoi 鑲嵌。從隨機的點開始，讓它們透過鬆弛演算法演變。細胞互相推開直到達成平衡。依細胞大小、鄰居數量或與中心的距離著色。湧現出的有機拼貼感覺既隨機又必然。每一個種子都產生獨特的結晶之美——大師級生成演算法的標誌。

*以上是濃縮的範例。實際的演算法哲學應該是 4–6 段扎實的段落。*

### 核心原則
- **演算法哲學**：創造一種將透過程式碼表達的計算世界觀
- **過程重於成品**：永遠強調美是從演算法的執行中湧現的——每次執行都是獨一無二的
- **參數化表達**：想法透過數學關係、力、行為來溝通——而不是靜態構圖
- **藝術自由**：下一個 Claude 會以演算法詮釋這份哲學——提供實作上的創作空間
- **純粹的生成藝術**：這是在製作「活的演算法」，而不是加了隨機性的靜態圖片
- **專家工藝**：反覆強調最終的演算法必須感覺精雕細琢、經過無數次迭代精修，是計算美學領域頂尖人物深厚專業的成果

**演算法哲學應為 4–6 段。** 用詩意的計算哲學填滿它，匯聚預期的願景。避免重複相同的論點。將這份演算法哲學輸出為 .md 檔。

`templates/viewer.html` 檔是基礎。它包含所需的確切結構與樣式。

  - 上一個/下一個按鈕

- 側邊欄中的動作區塊：
  - 重新生成按鈕
  - 重設按鈕

**可變（每件作品各自客製）：**
- 整個 p5.js 演算法（setup/draw/類別）

  - 參數名稱

  - 有些作品需要顏色選擇器
  - 有些作品可能使用固定的顏色
  - 有些作品可能是單色的（不需要顏色控制項）

**每件作品都應該有獨特的參數與演算法！** 固定的部分提供一致的使用體驗——其他一切都在表達獨特的願景。

## 創作過程

**使用者請求** → **演算法哲學** → **實作**

每個請求都是獨一無二的。過程包括：

1. **詮釋使用者的意圖** ——追求的是什麼美學？
2. **創作演算法哲學**（4–6 段），描述計算的做法
3. **以程式碼實作它** ——建構表達這份哲學的演算法
4. **設計適當的參數** ——哪些應該可以調校？
5. **建構相符的 UI 控制項** ——為那些參數提供滑桿/輸入框

**不變的部分**：
- Anthropic 品牌（色彩、字型、版面）
- 種子導覽（一律存在）
- 自成一體的 HTML artifact

**其他一切都是可變的**：
- 演算法本身
- 參數
- UI 控制項
- 視覺結果

要達到最佳成果，相信創意，讓哲學引導實作。

## 資源

本技能包含有用的模板與文件：

- **templates/viewer.html**：所有 HTML artifact 的必要起點。
  - 這是基礎——包含確切的結構與 Anthropic 品牌
  - **保持不變**：版面結構、側邊欄組織、Anthropic 色彩/字型、種子控制、動作按鈕
  - **替換**：p5.js 演算法、參數定義，以及參數區塊中的 UI 控制項
  - 檔案中大量的註解確切標示了哪些要保留、哪些要替換

- **templates/generator_template.js**：p5.js 最佳實踐與程式碼結構原則的參考。
  - 示範如何組織參數、使用帶種子的隨機性、建構類別
  - 「不是」一份圖樣菜單——用這些原則來打造獨特的演算法
  - 把演算法內嵌在 HTML artifact 中（不要建立獨立的 .js 檔）

**關鍵提醒**：
- **模板是「起點」**，而不是靈感
- **演算法**才是創作獨特之物的地方
- 不要照抄流場範例——打造哲學所要求的東西
- 但「要」保留模板中確切的 UI 結構與 Anthropic 品牌
