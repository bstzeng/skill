# 根本原因追溯

## 概覽

Bug 常常在呼叫堆疊的深處才顯現（git init 在錯誤的目錄執行、檔案建立在錯誤的位置、資料庫以錯誤的路徑開啟）。你的直覺是在錯誤出現的地方修正，但那是在治標。

**核心原則：** 沿著呼叫鏈往回追溯，直到找到最初的觸發點，然後在源頭修正。

## 真實案例：空的 projectDir

**症狀：** `.git` 被建立在 `packages/core/`（原始碼）中

**追溯鏈：**
1. `git init` 在 `process.cwd()` 中執行 ← 空的 cwd 參數
2. WorktreeManager 被以空的 projectDir 呼叫
3. Session.create() 被傳入空字串
4. 測試在 beforeEach 之前就存取了 `context.tempDir`
5. setupCoreTest() 一開始回傳 `{ tempDir: '' }`

**根本原因：** 頂層變數的初始化存取到了空值

**修正：** 把 tempDir 改成 getter，在 beforeEach 之前被存取時就拋出錯誤

**也加入了縱深防禦：**
- 第 1 層：Project.create() 驗證目錄
- 第 2 層：WorkspaceManager 驗證不為空
- 第 3 層：NODE_ENV 守衛拒絕在暫存目錄之外執行 git init
- 第 4 層：在 git init 之前記錄堆疊追蹤

## 堆疊追蹤提示

**在測試中：** 使用 `console.error()` 而不是 logger——logger 可能被抑制
**在操作之前：** 在危險操作之前記錄，而不是在它失敗之後
**包含脈絡：** 目錄、cwd、環境變數、時間戳
**擷取堆疊：** `new Error().stack` 會顯示完整的呼叫鏈
