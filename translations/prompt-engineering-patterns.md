# 提示工程模式

掌握進階的提示工程技巧，以最大化 LLM 的效能、可靠性與可控性。

## 何時使用本技能

- 為生產環境的 LLM 應用設計複雜的提示詞
- 最佳化提示詞的效能與一致性
- 實作結構化推理模式（思維鏈、思維樹）
- 建立具備動態範例選擇的少樣本學習系統
- 建立含變數插值、可重用的提示範本
- 除錯並修正會產生不一致輸出的提示詞
- 為專門的 AI 助理實作系統提示
- 使用結構化輸出（JSON 模式）以便可靠地解析

## 核心能力

### 1. 少樣本學習（Few-Shot）

- 範例選擇策略（語意相似度、多樣性抽樣）
- 在範例數量與上下文視窗限制之間取得平衡
- 以輸入—輸出配對建構有效的示範
- 從知識庫動態檢索範例
- 透過策略性的範例選擇處理邊界情況

### 2. 思維鏈提示（Chain-of-Thought）

- 引導逐步推理
- 以「讓我們一步一步思考」進行零樣本 CoT
- 帶推理過程的少樣本 CoT
- 自我一致性技巧（抽樣多條推理路徑）
- 驗證與確認步驟

### 3. 結構化輸出

- 用 JSON 模式以便可靠地解析
- 以 Pydantic 強制執行結構
- 型別安全的回應處理
- 處理格式錯誤的輸出

### 4. 提示詞最佳化

- 迭代修正的工作流程
- A/B 測試提示詞變體
- 衡量提示詞的效能指標（準確度、一致性、延遲）
- 在維持品質的同時減少 token 用量
- 處理邊界情況與失敗模式

### 5. 範本系統

- 變數插值與格式化
- 條件式的提示段落
- 多輪對話範本
- 以角色為基礎的提示組合
- 模組化的提示元件

### 6. 系統提示設計

- 設定模型的行為與限制
- 定義輸出格式與結構
- 確立角色與專業
- 安全準則與內容政策
- 設定情境與背景資訊

## 最佳實務

1. **具體明確**：模糊的提示詞會產生不一致的結果
2. **用示範，不要只用說的**：範例比描述更有效
3. **使用結構化輸出**：用 Pydantic 強制結構以確保可靠
4. **廣泛測試**：在多樣、具代表性的輸入上評估
5. **快速迭代**：小改動可能有大影響
6. **監控效能**：在生產環境中追蹤指標
7. **版本控制**：把提示詞當成程式碼，妥善管理版本
8. **記錄意圖**：說明提示詞為什麼這樣設計

## 常見陷阱

- **過度設計**：還沒試過簡單的提示詞就從複雜的開始
- **範例污染**：使用與目標任務不符的範例
- **上下文溢出**：過多的範例超出 token 上限
- **指示模稜兩可**：留下多種解讀的空間
- **忽略邊界情況**：沒有在不尋常或邊界的輸入上測試
- **沒有錯誤處理**：假設輸出永遠格式正確
- **寫死數值**：沒有把提示詞參數化以便重用

## 成功指標

為你的提示詞追蹤這些 KPI：

- **準確度**：輸出的正確性
- **一致性**：在相似輸入間的可重現性
- **延遲**：回應時間（P50、P95、P99）
- **Token 用量**：每次請求的平均 token 數
- **成功率**：有效、可解析之輸出的百分比
- **使用者滿意度**：評分與回饋
