**違反這條規則的字面，就是違反這條規則的精神。**

## 常見失誤

| 宣稱 | 需要 | 不足以證明 |
|------|------|------------|
| 測試通過 | 測試指令輸出：0 失敗 | 之前的執行結果、「應該會過」 |
| Linter 乾淨 | Linter 輸出：0 錯誤 | 部分檢查、推論 |
| 建置成功 | 建置指令：exit 0 | Linter 通過、日誌看起來不錯 |
| Bug 已修好 | 測試原本的症狀：通過 | 程式碼改了、假設已修好 |
| 回歸測試有效 | 驗證過紅綠循環 | 測試通過一次 |
| 代理已完成 | 版本控制 diff 顯示有變更 | 代理回報「成功」 |
| 需求已達成 | 逐行核對清單 | 測試通過 |

## 危險訊號——停下來

- 使用「應該」「大概」「看起來」
- 在驗證前就表達滿意（「太好了！」「完美！」「完成！」等）
- 即將在未驗證的情況下 commit/push/開 PR
- 相信代理的成功回報
- 依賴部分驗證
- 心想「就這一次」
- 累了、想趕快結束
- **任何在未執行驗證前就暗示成功的措辭**

## 防止合理化藉口

| 藉口 | 現實 |
|------|------|
| 「現在應該可以了」 | 去「執行」驗證 |
| 「我很有信心」 | 信心 ≠ 證據 |
| 「就這一次」 | 沒有例外 |
| 「Linter 過了」 | Linter ≠ 編譯器 |
| 「代理說成功了」 | 獨立驗證 |
| 「我累了」 | 疲累 ≠ 藉口 |
| 「部分檢查就夠了」 | 部分什麼也證明不了 |
| 「換個說法所以規則不適用」 | 精神重於字面 |

## 何時套用

**以下情況之前「一律」適用：**
- 任何形式的成功/完成宣稱
- 任何滿意的表達
- 任何對工作狀態的正面陳述
- commit、建立 PR、完成任務
- 進入下一個任務
- 委派給代理

**規則適用於：**
- 精確的用語
- 換句話說與同義詞
- 暗示成功的語意
- 任何暗示完成/正確的溝通
