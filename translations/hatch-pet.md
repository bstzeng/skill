# 孵化寵物

## 概覽

從一個概念、品牌線索、公司／潛在客戶名稱、一張或多張參考圖片，或上述的任意組合，建立相容於 Codex 的動畫寵物。這個工作流程保留確定性的 hatch-pet 流水線來處理圖集幾何、驗證、目視 QA 與打包，同時使用精簡、針對各狀態的提示詞，並允許任何適合寵物的視覺風格。

面向使用者的輸入都是選填的。如果使用者沒給寵物名字，就從概念、品牌、公司或參考檔名推斷一個；如果無法推斷，就選一個簡短友善的名字。如果使用者沒給描述，就從概念或參考推斷。如果使用者沒給參考圖片，就先從文字生成基準寵物，再把那張基準圖當作每一列動畫的正式參考。

呼叫 `$imagegen` 時，把產生的寵物提示詞當作權威的視覺規格傳入。寵物提示詞應保持精簡、針對狀態、以精靈圖製作為導向，並以列出的輸入圖片為依據。較長的政策與 QA 規則留在本技能與確定性的審查腳本中，不要擴寫進每一個圖片提示詞。不要把提示詞包進 `$imagegen` 的通用共用提示詞結構。

本技能的腳本只用於確定性的圖片工作：準備版面導引與提示詞、鏡像已核准的 `running-left`、擷取影格、驗證列、組合最終圖集，以及建立對照表與動態預覽的 QA 媒體。由父代理負責的 shell／`jq` 步驟處理清單更新、打包與清理。

## 儲存控制

內建的 `$imagegen` 路徑會把生成的 PNG 位元組存進呼叫它的 rollout 中，即使它同時也在 `${CODEX_HOME:-$HOME/.codex}/generated_images` 下寫入檔案。之後刪除檔案可以減少檔案系統用量，但無法縮小已經寫入的 rollout。保持圖片生成的隔離與受限：

- 每個視覺工作使用一個輕量生成 worker。不要把多個基準／列工作批次塞進同一個 worker。
- Worker 只能回傳 `selected_source=...` 與 `qa_note=...`；最終回應中不得包含 Markdown 圖片預覽、base64 或額外的視覺附件。
- 父代理不得目視開啟每一張生成的 PNG。每個工作使用 worker 的 QA，只檢查最終的對照表。
- 把選定的生成輸出複製到 `decoded/` 之後，如果選定的原始檔位於 `${CODEX_HOME:-$HOME/.codex}/generated_images`，就把它刪除，並在可能時移除已清空的生成目錄。
- 對於在意儲存空間的完整執行，在可用時詢問使用者是否要使用 `$imagegen` 的 CLI 備案。該路徑需要本機 API 憑證與使用者的明確確認，但可以避免內建圖片資料被嵌入 rollout 事件中。

## 品牌探索

如果使用者提供的是品牌、公司、產品或潛在客戶名稱，而不是具體的頭像描述或參考圖片，就在準備寵物執行之前，先執行一個輕量的探索子代理。探索 worker 必須使用網路搜尋，並優先採用官方來源，例如品牌網站、產品頁、文件、關於我們頁面、新聞頁或品牌頁。只有在官方頁面太單薄時才使用信譽良好的次要來源。搜尋範圍要窄：足以擷取視覺與個性線索即可，不是市場研究簡報。

如果使用者已經提供具體的吉祥物／頭像描述或參考圖片，就跳過探索，除非使用者明確要求品牌研究。

探索 worker 的職責：

- 在網路上搜尋 2–4 個相關來源，優先採用官方頁面
- 撰寫一份有彈性的 markdown 簡報，而不是死板的欄位傾印
- 涵蓋身分／類別、受眾／使用情境、視覺系統、個性／語氣、產品／領域圖騰、吉祥物轉譯線索、要避免的事物，以及證據／信心程度
- 把從來源推斷出的吉祥物指引標示為推斷
- 避免複製商標、可辨識的標誌、UI 截圖、標語或文字
- 結尾附上精簡的 `Generation handoff` 章節，只包含 `brand_name`、`brand_brief`、`avatar_seed`、`avoid` 與 `brand_sources`
- 不要生成圖片、準備執行資料夾或編輯無關的檔案

一次正常的寵物執行，預期最多有 10 個視覺生成工作：1 個基準寵物加上 9 個列條帶工作。Codex App 的合約目前使用全部 9 種狀態：`idle`、`running-right`、`running-left`、`waving`、`jumping`、`failed`、`waiting`、`running` 與 `review`。唯一的確定性視覺衍生是 `running-left`，只有在 `running-right` 已經生成、目視檢查，並明確核准可安全鏡像之後，才能透過鏡像 `running-right` 產生。如果鏡像不適當，就把 `running-left` 當作一般有依據的 `$imagegen` 列來生成。

選定一個視覺輸出後，父代理把那張圖片原封不動地複製到該工作的 `decoded/` 路徑，並在 `imagegen-jobs.json` 中把工作標記為完成。不要撰寫填入列輸出的輔助腳本。確定性的 Python 腳本只能處理已經生成的視覺輸出。

只有基準工作可以只靠提示詞。每一個透過 `$imagegen` 生成的列條帶工作，都必須使用 `imagegen-jobs.json` 中列出的輸入圖片，包括在複製選定的基準輸出後建立的正式基準參考。任何沒有附上依據圖片的列生成都視為無效。

## 適合寵物的風格

預設風格是 `auto`：從使用者的提示詞與參考推斷寵物風格，然後在每一列中保持那個風格。如果使用者指定了風格，就遵照。支援的風格預設包括 `pixel`、`plush`、`clay`、`sticker`、`flat-vector`、`3d-toy`、`painterly`、`brand-inspired` 與 `auto`。

只要仍適合寵物，任何風格都可以接受：

- 在 `192x208` 的格子內可辨識的緊湊全身輪廓
- 所有列中的臉、比例、材質、配色與道具一致
- 乾淨、可移除的色鍵背景
- 細節夠大，在寵物尺寸下仍可辨識
- 沒有文字、標籤、UI 或可辨識的商標，除非使用者明確提供了核准的參考美術並要求加入

非像素風格是一等公民。絨毛玩偶、黏土、貼紙、向量、3D 玩具、繪畫風吉祥物、墨水與品牌啟發的外觀，只要滿足圖集與可辨識度的限制，都應該被接受。

## 透明度與特效

寵物列會被處理成透明的 `192x208` 格子，所以每一個生成的像素都必須屬於寵物精靈，或是可以乾淨移除的色鍵背景。偏好用姿勢、表情與輪廓的變化，而不是裝飾性的特效。

確定性的點陣流水線負責透明度的不變條件：變成完全透明的像素會被正規化，不保留隱藏的 RGB 殘留；如果匯出的檔案違反這個不變條件，圖集驗證就應該失敗。不要靠接受視覺上不一致的輸出來掩蓋彩色光暈或透明像素殘留。

允許的特效必須滿足以下所有條件：

- 特效與狀態相關，並有助於說明動畫。
- 特效在物理上依附、接觸或重疊在寵物輪廓上，而不是飄在附近。
- 特效與寵物位於同一個影格槽位內，且不會形成獨立的精靈元件。
- 特效是不透明的、邊緣夠硬以便乾淨擷取，並使用非色鍵的顏色。
- 特效夠小，在 `192x208` 下仍可辨識且不雜亂。

預設避免以下這些，因為它們通常會破壞透明背景的清理或元件擷取：

- 揮動線、動作弧線、速度線、動作條紋、殘影、模糊或拖影
- 分離的星星、零散的閃光、漂浮的標點、漂浮的圖示、掉落的淚滴、分離的煙霧或散落的灰塵
- 投影、接觸陰影、下落陰影、橢圓形地面陰影、地面色塊、落地痕跡、衝擊爆發、發光、光暈、光環或柔和的透明特效
- 文字、標籤、影格編號、可見的格線、導引標記、對話框、思考泡泡、UI 面板、程式碼片段、棋盤格透明、白色背景、黑色背景或場景
- 寵物、道具、特效、高光或陰影中出現接近色鍵的顏色
- 雜散像素、斷開的輪廓碎片、斑點／雜訊、被裁切的身體部位、重疊的姿勢，或任何越過到相鄰影格槽位的姿勢

各狀態專屬的指引：

- `idle`：保持平靜、低干擾。只使用細微的呼吸、小小的眨眼、輕微的頭部或身體上下晃動、非常小的材質擺動，或其他安靜、維持個性的動作。循環中仍必須有可見的微小變化；不要接受六張實際上一模一樣的複本。不要表現揮手、走路、跑步、跳躍、說話、工作、審查、情緒反應、大幅手勢、物品互動或新道具。
- `waving`：只透過爪子、手、翅膀或肢體的姿勢表現揮手。不要在手勢周圍畫揮動線、動作弧線、線條、閃光、符號或漂浮特效。
- `jumping`：只透過身體位置表現垂直運動。不要畫陰影、灰塵、落地痕跡、衝擊爆發、彈跳墊或地面線索。
- `failed`：如果遵守允許特效的規則，可以有眼淚、依附的煙霧或依附的星星；不要使用紅色 X 記號、漂浮符號、分離的煙霧、分離的星星或分開的淚滴。
- `waiting`：透過期待、詢問的姿勢，表現 Codex 需要核准、幫助或使用者輸入。與一般的 idle 和 review 保持區隔。
- `running`：表現正在進行任務、處理中、思考、掃描、打字或專注努力。不要表現字面上的用腳跑步、慢跑、衝刺、跑步機動作、抬高膝蓋、大步伐、擺動手臂、有方向的移動、速度線、塵雲、地面陰影、動作軌跡或分離的動作特效。
- `review`：透過前傾、眨眼、眼神、歪頭或爪子／手的位置表現專注。不要加入放大鏡、紙張、程式碼、UI、標點、符號或其他新道具，除非它們本來就存在於基準寵物的身分中。
- `running-right` 與 `running-left`：只透過身體、肢體與道具的動作表現有方向的拖曳移動。`running-right` 必須面向右並往右移動；`running-left` 必須面向左並往左移動。它們的節奏必須在循環中明顯交替，而不是重複一個幾乎靜止的步伐。不要畫速度線、塵雲、地面陰影、動作軌跡或分離的動作特效。

## 可見的進度計畫

每次寵物執行都要維持一份可見的檢查清單，讓使用者看得到工作進行到哪裡。在開始前建立檢查清單，一次只讓一個步驟處於進行中，並在每個步驟完成時更新。

一般寵物執行使用這份檢查清單，把 `<Pet>` 換成寵物的名字或「你的寵物」：

1. 正在幫 `<Pet>` 做準備。
2. 正在想像 `<Pet>` 的主要外觀。
3. 正在描繪 `<Pet>` 的各種姿勢。
4. 正在孵化 `<Pet>`。

每個步驟的意思：

- `正在幫 <Pet> 做準備。` 選擇或確認寵物名字、描述、來源圖片、風格預設、風格備註與工作資料夾。對於只有品牌／產品／公司名稱的請求，先執行品牌探索 worker，並取得精簡的品牌簡報、來源 URL 與頭像種子。
- `正在想像 <Pet> 的主要外觀。` 生成寵物的主要參考圖片。這會成為視覺上的唯一依據。
- `正在描繪 <Pet> 的各種姿勢。` 透過輕量 worker 生成姿勢列，從 `idle` 與 `running-right` 開始，以確認身分與步態。只有在 `running-right` 翻轉後明顯可行時，才鏡像產生 `running-left`。
- `正在孵化 <Pet>。` 把核准的姿勢轉成最終的寵物檔案，檢查對照表、預覽與驗證結果，修好任何壞掉的部分，儲存 `pet.json` 與 `spritesheet.webp`，然後回報輸出路徑。

只有在真正的檔案、圖片或決定存在時，才把步驟標記為完成。如果這是修復執行，就從第一個相關步驟開始，而不是重新跑整份清單。

預設用輕量子代理處理圖片密集的工作。這把每個 `$imagegen` rollout 限制在一張選定的圖片、讓對照表的視覺資料不進入父執行緒，並在保留完整 9 狀態 App 合約的同時降低成本。

## 子代理委派

除非使用者明確禁止，否則這次執行要使用子代理。如果使用者尚未允許使用子代理，或對子代理使用的意圖不明確，就詢問使用者是否允許產生子代理來平行處理工作。

父代理的職責：

- 當使用者提供光禿禿的品牌／產品／公司／潛在客戶名稱時，在準備之前執行品牌探索 worker
- 準備執行並檢查 `imagegen-jobs.json`
- 把基準工作、列工作與最終對照表 QA 指派給輕量 worker
- 把選定的 worker 輸出複製到解碼路徑，並在 `imagegen-jobs.json` 中把工作標記為完成
- 從選定的基準輸出建立 `references/canonical-base.png`
- 在適當時執行已核准的 `running-left` 鏡像衍生
- 執行確定性的圖片處理、打包、修復重新生成與清理

基準 worker 的職責：

- 只處理 `base` 工作
- 讀取 `prompts/base-pet.md` 並使用任何列出的參考圖片
- 只使用 `$imagegen`
- 把提示詞中任何精簡的品牌靈感行當作大方向的視覺／個性指引，不複製商標、可辨識的標誌、UI 截圖、標語或文字
- 只回傳 `selected_source=/absolute/path/to/selected-output.png` 與 `qa_note=<一句話>`

列 worker 的職責：

- 只處理剛好一個列工作
- 讀取列提示詞並使用所有列出的輸入圖片
- 只使用 `$imagegen`；不要在本機繪製、編輯、拼貼或合成精靈圖
- 快速目視檢查影格數、身分、色鍵背景、間距、裁切與分離的特效
- 執行列提示詞的透明度與特效規則，包括：沒有分離的特效、`waving` 沒有揮動線、有方向的跑步列沒有速度線或灰塵、非方向性的 `running` 列沒有字面上的用腳跑步，以及只有在狀態提示詞允許時才有依附、不透明、像精靈圖的眼淚／煙霧／星星
- 只回傳 `selected_source=/absolute/path/to/selected-output.png` 與 `qa_note=<一句話>`

最終目視 QA worker 的職責：

- 檢查 `qa/contact-sheet.png` 以及 `qa/previews/` 下的列 GIF，在有用時以 `qa/review.json` 與 `final/validation.json` 作為文字情境

## 修復工作流程

如果影格檢查或最終目視 QA 失敗，讀取 `qa/review.json`，重新生成最小的失敗範圍，把替換的列複製到同一個解碼輸出路徑，並讓該工作維持標記為完成，更新 `source_path` 與 `completed_at`。修復失敗的那一列，而不是整張圖。

對於身分修復，使用正式基準圖、原始參考、對照表與確切的列失敗備註作為依據情境。給列 worker 既有的列提示詞，加上來自 `qa/review.json` 的精簡修復備註；保留正式的寵物身分與選定的風格。

對於擷取造成的動作跳動，不要先重新生成圖像。如果來源條帶已經保持列層級的比例與基準線，就用 `--method stable-slots` 重新執行確定性流水線，用 `--allow-stable-slots` 檢查，然後重新檢查預覽 GIF。只有在原始條帶本身被裁切、不穩定或語意錯誤時，才重新生成該列。

## 規則

- 保持 `$imagegen` 作為主要的生成層。
- 對於沒有具體頭像描述或參考圖片的品牌／產品／公司／潛在客戶請求，在生成基準之前執行品牌探索，並只把精簡簡報傳入執行。
- 使用 `$imagegen` 作為唯一的視覺生成層。不要從本技能呼叫圖片 API、圖片 CLI、本機點陣生成器或一次性的生成腳本。
- 只要選定的途徑支援參考，就讓參考圖片對 `$imagegen` 保持附上／可見。
- 每一個列條帶工作都要附上該列的 `references/layout-guides/<state>.png` 圖片作為僅限版面的導引，且不要接受複製了導引像素的輸出。
- 預設用輕量視覺 worker 進行基準生成、列條帶視覺生成與最終對照表 QA；父代理負責清單更新、確定性圖片腳本、打包與清理。
- 每一個一般視覺工作都用 `$imagegen` 生成：基準加上所有非經明確核准之 `running-left` 鏡像衍生的列條帶。
- 只有基準工作有資格只靠提示詞生成；每一個列工作都必須附上它列出的依據圖片。
- 先生成 `running-right`，再決定 `running-left` 能否鏡像。
- 鏡像產生 `running-left` 時，保留影格順序與時序語意；透過確定性腳本衍生，而不是把整條直接鏡像。
- 不要從其他狀態衍生或重用 `waiting`、`running`、`failed`、`review`、`jumping` 或 `waving`；每一個都有不同的 App 語意，必須作為獨立的列生成。
- 絕不要用本機繪製、拼貼、轉換或程式產生的列條帶取代缺少的 `$imagegen` 輸出。
- 只有在選定的輸出已被複製到解碼輸出路徑之後，才把視覺工作標記為完成。
- 不要依賴生成的圖片來達成精確的圖集幾何；使用本技能的確定性圖片腳本。
- 使用 `pet_request.json` 中儲存的色鍵；不要強制使用固定的綠幕。
- 在所有列中保持寵物的輪廓、臉、材質、配色、風格與道具一致。
- 即使 `qa/review.json` 與 `final/validation.json` 沒有錯誤，也要把視覺身分或風格漂移視為阻擋項目。
- 把出現裁切的參考、重複的拼貼、白色格子背景或非精靈圖碎片的對照表視為失敗。
- 把顯示擷取造成的尺寸跳動、反轉的方向時序、錯誤面向或毫無動靜的待機循環的預覽 GIF 視為失敗。
- 把出現禁止的分離特效、接近色鍵的瑕疵、陰影、發光、拖影、灰塵、落地痕跡、揮動線、速度線或動作軌跡的列視為失敗。
- 把 `qa/review.json` 的錯誤視為阻擋項目。警告需要目視審查。

## 驗收標準

- 最終圖集為 PNG 或 WebP，`1536x1872`，支援透明，並以 `192x208` 的格子為基礎。
- 使用中的格子不為空，未使用的格子完全透明。
- 圖集遵循 `references/animation-rows.md` 中的列／影格數。
- 對照表與各列的動態預覽已經產生，並由輕量目視 QA worker 檢查過。
- `qa/review.json` 沒有錯誤。
- 逐列審查確認動畫循環對 Codex App 來說足夠完整。
- 動態預覽沒有顯示非預期的尺寸跳動、反轉的方向節奏或錯誤的列語意。
- 非像素風格只要在寵物尺寸下可辨識且各列一致，就被接受。
- 自訂寵物的 `${CODEX_HOME:-$HOME/.codex}/pets/<pet-name>/pet.json` 與 `${CODEX_HOME:-$HOME/.codex}/pets/<pet-name>/spritesheet.webp` 一起準備就緒。
