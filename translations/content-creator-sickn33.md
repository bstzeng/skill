# 內容創作者

使用提供的品牌範例、本機文字診斷與可調整的通路範本，起草並審閱針對特定受眾的內容。

## 何時使用
在撰寫部落格文章、建立社群媒體內容、建立品牌語氣、為 SEO 最佳化內容或規劃內容行事曆時使用本技能。

## 關鍵字
內容創作、部落格文章、SEO、品牌語氣、社群媒體、內容行事曆、行銷內容、內容策略、內容行銷、品牌一致性、內容最佳化、社群媒體行銷、內容規劃、部落格寫作、內容框架、品牌指南、社群媒體策略

## 輸入與邊界

取得受眾、目的、核准的主張與來源、品牌範例、通路，以及期望的下一步行動。重用提供的限制條件；不要捏造受眾研究。選用的本機腳本只需要 Python 3。從本技能目錄執行範例，輸入必須是工作目錄底下、經允許的 UTF-8 檔案（最大 1 MiB）；其他位置的路徑會被拒絕。腳本會讀取該檔案並印出診斷，不會呼叫分析服務，也不會編輯它。分享輸出之前，先審閱其中任何私人文字。起草不代表獲准排程、發送或發布。

## 快速開始

### 建立品牌語氣
1. 對既有內容執行 `scripts/brand_voice_analyzer.py`，記錄大略的詞彙特徵
2. 閱讀 `references/brand_guidelines.md` 選擇語氣屬性
3. 在所有內容中一致地套用選定的語氣

### 建立部落格內容
1. 從 `references/content_frameworks.md` 選擇範本
2. 為主題研究關鍵字
3. 依照範本結構撰寫內容
4. 執行 `scripts/seo_optimizer.py [file] [primary-keyword]` 進行最佳化
5. 發布前，對照受眾與實際頁面審閱建議

### 社群媒體內容
1. 閱讀 `references/social_media_optimization.md` 中的平台最佳實務
2. 使用 `references/content_frameworks.md` 中適當的範本
3. 依照平台專屬指引最佳化
4. 使用 `assets/content_calendar_template.md` 排程

## 核心工作流程

### 建立品牌語氣（首次設定）

為新品牌或新客戶建立內容時：

1. **分析既有內容**（如果有的話）
   ```bash
   python scripts/brand_voice_analyzer.py existing_content.txt
   ```
   
2. **定義語氣屬性**
   - 閱讀 `references/brand_guidelines.md` 中的品牌個性原型
   - 選擇主要與次要原型
   - 選擇 3–5 個語調屬性
   - 記錄在品牌指南中

3. **建立語氣範例**
   - 用選定的語氣寫 3 篇範例
   - 以人工方式與核准的範例比較；分析器只用來提供詞彙線索
   - 依結果調整

### 建立 SEO 最佳化的部落格文章

1. **關鍵字研究**
   - 從實際的研究中找出讀者的問題與相關的搜尋意圖
   - 記錄這篇文章需要回答的相關問題
   - 不要捏造搜尋量，也不要把字詞頻率當成語意研究

2. **內容結構**
   - 使用 `references/content_frameworks.md` 中的部落格範本
   - 使用描述性的標題與小標；自然地使用讀者的用語
   - 用足夠的細節回答問題；SEO 沒有通用的字數標準

3. **最佳化檢查**
   ```bash
   python scripts/seo_optimizer.py blog_post.md "primary keyword" "secondary,keywords,list"
   ```

4. **套用 SEO 建議**
   - 移除有損清晰度的重複；不要以某個關鍵字密度百分比為目標
   - 確保正確的標題結構
   - 加入內部與外部連結
   - 最佳化 meta 描述

### 建立社群媒體內容

1. **選擇平台**
   - 依受眾找出主要平台
   - 閱讀 `references/social_media_optimization.md` 中的平台專屬指引

2. **內容改寫**
   - 從部落格文章或核心訊息開始
   - 使用 `references/content_frameworks.md` 中的再利用矩陣
   - 依照範本為各平台改寫

3. **最佳化檢查清單**
   - 適合平台的長度
   - 依受眾資訊決定要測試的發文時間
   - 正確的圖片尺寸
   - 平台專屬的主題標籤
   - 互動元素（投票、提問）

### 規劃內容行事曆

1. **每月規劃**
   - 複製 `assets/content_calendar_template.md`
   - 設定每月目標與 KPI
   - 找出主要的活動／主題

2. **每週分配**
   - 依目標、製作能量與觀察到的受眾需求選擇內容組合
   - 在一週內平衡各平台
   - 標示尚未測試的時間假設，並在明確的期間內比較結果

3. **批次製作**
   - 在一次工作時段內製作整週的內容
   - 在各篇之間保持一致的語氣
   - 一起準備所有視覺素材

## 主要腳本

### brand_voice_analyzer.py
計算一小組英文詞彙的出現次數，並估算句子長度／可讀性。它無法確立真實的品牌語氣，也無法驗證事實主張。

**用法**：`python scripts/brand_voice_analyzer.py <file> [json|text]`

**回傳**：
- 語氣輪廓（正式程度、語調、觀點）
- 可讀性分數
- 句子結構分析
- 改善建議

### seo_optimizer.py
分析內容的 SEO 最佳化程度，並提供可執行的建議。

**用法**：`python scripts/seo_optimizer.py <file> [primary_keyword] [secondary_keywords]`

**回傳**：
- 描述性的文字診斷（沒有排名或品質分數）
- 關鍵字密度分析
- 結構評估
- Meta 標籤建議
- 具體的最佳化建議

## 實作範例：一個來源，兩份草稿

對於一則核准的發布說明，內容是「現在可以匯出 CSV」，準備一篇簡短的說明文章，解釋匯出功能在哪裡，以及一則連結到該文章的社群草稿。保留來源中確切支援的格式與限制。沒有實測證據時，不要把這個主張變成「節省好幾個小時」。執行本機文字診斷，然後對照實際產品驗證操作說明，並與兩則核准的貼文比較語調。交回兩份草稿、來源連結、尚未釐清的事實，以及建議的行事曆時段。預期結果：可供審閱的文案；沒有任何貼文被送出。

## 限制

- 內附的分析器使用小型英文詞表與近似的音節計算；平手或沒有符合時，並不代表能辨識品牌個性。它不是經驗證的閱讀評估，也無法可靠地支援多語言評分。
- SEO 輔助工具檢查的是簡單的 Markdown 模式，而不是渲染後的頁面、索引、搜尋需求、無障礙、排名或因果關係。字元長度與字數是觀察，不是品質門檻。
- 範本包含示意用的佔位內容，不是推薦語、基準數據或客戶事實。對引用的素材與圖片，要確認權利與核准。
- 通路功能會改變。針對選定的格式，查看目前的原生編輯器與官方說明；用帳號分析數據測試時間，而不是套用通用規則。

Google 的 [以人為本的內容指引](https://developers.google.com/search/docs/fundamentals/creating-helpful-content) 說明了為什麼滿足讀者需求比填滿目標字數更重要。
