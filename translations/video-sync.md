## video-sync

把 **shots.json + 原片** 合成一條影片：畫面一邊，**當前鏡頭的分鏡資訊**另一邊，
鏡頭切了資訊跟著切，鏡頭表自動滾動並高亮。

**版式只看寬高比，不看別的：**

| 原片 | 版式 | 合成方式 |
| --- | --- | --- |
| 橫版（寬 > 高）、方版 | **畫面在上，資訊在下** | `vstack` |
| 豎版（高 > 寬） | **畫面在左，資訊在右** | `hstack` |

兩個方向都保證**畫面原樣縮放、不裁不拉**，面板補足剩下的地方。

**只截三張圖，動的部分交給 ffmpeg。** 面板上會變的只有兩樣：滾到哪、哪一行亮。
所以量一次行位置、截一張底板、截兩張把鏡頭表鋪開的長圖（一張壓暗、一張全亮），
滾動＝從暗底長圖裁一個視窗，高亮＝從亮條長圖裁一行蓋上去，位置由 `sendcmd`
在每個切點下發一條小表示式驅動。53 鏡的片子截圖從 53 次降到 3 次（12 秒）。

**當前鏡頭釘在第二行**：第 1、2 鏡不滾（高亮往下挪一行），第 3 鏡起每切一次往上滾一行。
**動在切點，靜在鏡頭裡**——切點處滾 `--ease`（預設 0.45）秒到位就停住，
16 秒的長鏡頭裡讓列表一直爬，觀眾要盯著它晃 16 秒。

**行高由內容決定**，描述寫得長行就高；高亮條按行高分層（`crop` 的高度執行時改不動）。

`{baseDir}` = 本檔案所在目錄。指令碼 `{baseDir}/scripts/video-sync.mjs`，零依賴，`node` 直接跑。

**邊界（不做的事）**：不做拉片（那是 `video-shots` 的活，本 skill 吃它的 shots.json）、
不剪輯不轉場不配樂、不燒字幕到畫面上、不做逐幀渲染（動效由 ffmpeg 按時間裁窗做出來）。

### Step 0 — 先有拉片資料

要一份 `shots.json`（`video-shots` 的產出）和**對應的原片**。有 `frames/`（每鏡關鍵幀）
更好——鏡頭表裡會用起手幀當縮圖，沒有就留空格。

**shots.json 必須和這條片子對得上**：`meta.durationSeconds` 與原片不符就別合，
先回去把拉片做對。

### Step 1 — 先看幾何，再動影片

{{CODE:1}}

只算不合成，幾秒出結果：版式、畫面區、面板區、輸出尺寸。**先確認這三個數字合理再往下走**——
合成一條 3 分鐘的片子要一兩分鐘，算錯了再重來不值。

不滿意就調：`--panel <比例>`（橫版是面板高÷畫面高，預設 0.8；豎版是面板寬÷畫面寬，預設 1.6）、
`--width` / `--height`（畫面區的上限，預設 1920 / 1080）。

**原片太小就放大畫面區**：面板是跟著畫面區算的，640×360 的片子面板只有 640×288，
四列擠在一起讀不了。`--scale 2` 把畫面區放到 1280×720、面板放到 1280×576，寬高比不動。
預設是 1（只縮不放）。`plan` / `panels` / `compose` / `export` 都要帶上同一個 `--scale`。

## 邊界

- **滾動只發生在切點**：滾 `--ease` 秒到位就停住，鏡頭裡面板是靜止的。
  真要做「全程勻速爬」也行（改 `motionPlan` 的分段），但長鏡頭會一直晃眼睛
- **需要一個無頭瀏覽器**（Chrome / Chromium / Edge）。這是「佈局能隨便改」的代價：
  換成 ffmpeg 的 `drawtext` 畫面板，中文換行、縮圖、高亮全得自己實現，改個版式要改濾鏡圖
- 詞表（景別 / 類別 / 運鏡 / 轉場）在本 skill 裡**自帶一份**，不跨目錄 import——
  skill 要能整個拷走。`video-shots` 那邊加了新詞，這邊也要加，不然顯示成列舉鍵
- 渲面板固定三張截圖，和鏡頭數無關：53 鏡約 12 秒。合成按片長走，203 秒的片子約 75 秒
