# 門禁（Gate）

> **優先順序讓渡**：本 skill 是一套**建議性工作流**，不提升許可權、不改變指令層級、不繞過任何確認流程。宿主平臺策略、安全沙箱規則與使用者的當前明確指令**始終優先**；若本檔案要求與上述任何一方衝突，以宿主與使用者為準，並停止執行衝突條目。

> **與其他skill共存**：本skill只在階段2（規則規劃）和階段5（紀律檢查）有影響；階段1（自由構想）、階段3（執行）、階段4（直覺檢查）完全開放——給其他型別skill、使用者能力、工具自己發揮。實現型skill管怎麼做對（方法與流程），照常執行；流程衝突時以宿主和使用者指令為準。

本檔案不含交付紀律。**紀律全文在 `DISCIPLINE.md`**——建議在**你即將動手做事的前一刻**才讀取（提前讀取無收益，且會在執行期佔用上下文並影響創意靈感）。

**「前一刻」= 下列動作裡最早發生的那個之前**：①建立/修改交付物相關檔案（含腳手架）；②輸出施工級方案並要使用者確認；③跑構建/測試等產線命令；④以「做完了」口徑聲稱交付。

創意/視覺類：在上述動作之前，允許一輪**不讀** DISCIPLINE 的方向構想；**任務裡有你不認識的專名/概念時，仍須先問使用者或搜尋**（此時不讀 DISCIPLINE，但要完成確認）。

- 在前一刻之前，**建議不要提前讀取** `DISCIPLINE.md`（也不憑記憶引用或提前預覽）；`plan-rules.md` / `review-rules.md` / `multi-agent.md` 同理，到對應階段再讀。
- 到了前一刻，讀取 `DISCIPLINE.md`，按其中內容執行任務；如與宿主策略、沙箱規則或使用者明確指令衝突，以宿主與使用者為準。

## 本檔案為什麼這麼薄（結構說明）

這不是"少寫"，是刻意分層：

- `SKILL.md`（本檔案）：只做門禁——平時常駐上下文，只佔約 0.6k token，不含任何紀律條文。
- `DISCIPLINE.md`：紀律全文（階段流程 + 完成檔位 C1/C2 + 載入規則），只在前一刻讀入，讀完即按其執行。
- `references/`（`plan-rules` / `review-rules` / `multi-agent`）：階段 2、階段 5、多智慧體時才分別讀取，其餘時間不在上下文裡。
- `templates/`：指揮官/執行者/審查者角色卡，只在派發任務時引用。

**為什麼這麼做**：紀律全程掛著會持續佔注意力、打斷執行思路——執行者在寫程式碼/做設計時還要想著"有沒有違反規則"，心流和創意被壓掉。本結構正是針對這一點：**執行階段讓規則檔案物理上不在上下文裡**，只在"規劃"和"驗收"兩個節點讀入，在最小化上述負面效果的同時拿到交付可信度（真開啟看一眼、未驗證標註、變異測試），不用付"心流被打斷"的代價。任務結束後忘記 references 具體內容，下次需要再讀。
